3D-графика в браузере без плагинов и боли

Three.js — самая популярная JavaScript-библиотека для 3D в вебе. Она берёт на себя низкоуровневую работу с видеокартой и даёт понятные объекты: сцену, камеру, свет, модели и материалы. Этот путеводитель объясняет, что она умеет, зачем её используют и как начать — с живыми примерами прямо на странице.

Что это

Three.js — слой между вами и WebGL

Браузеры умеют рисовать 3D через WebGL (а теперь и через более новый WebGPU). Но это очень низкоуровневые интерфейсы: чтобы вывести на экран хотя бы один цветной треугольник на чистом WebGL, нужно написать шейдеры на языке GLSL, скомпилировать их, создать буферы, разметить атрибуты и вручную посчитать матрицы проекции. Это десятки строк ради одного треугольника.

Three.js прячет всё это за привычными понятиями из 3D-редакторов. Вы создаёте сцену, ставите камеру, добавляете куб, включаете свет — и библиотека сама превращает это в команды для видеокарты. Её создал Рикардо Кабельо (mrdoob) в 2010 году, сейчас она развивается сообществом с открытым исходным кодом и выходит примерно раз в месяц (номера версий вида r170).

Чистый WebGL

  • Писать вершинный и фрагментный шейдеры вручную
  • Компилировать и связывать программы, ловить ошибки
  • Создавать буферы и описывать атрибуты вершин
  • Считать матрицы камеры и перспективы самому
  • Свет, тени, текстуры — всё с нуля

Three.js

  • new THREE.Mesh(geometry, material)
  • Готовые материалы, включая физически корректные (PBR)
  • Камеры, свет и тени включаются одной строкой
  • Загрузчики моделей, текстур и анимаций
  • При желании — доступ к своим шейдерам

Зачем

Преимущества

Почему из всех 3D-инструментов для веба чаще всего выбирают именно Three.js.

Низкий порог входа

Понятный объектный API. Первую вращающуюся фигуру можно сделать за 20 строк — ниже на странице есть такой пример.

Огромное сообщество

Больше 100 тысяч звёзд на GitHub, сотни официальных примеров, активный форум. Почти на любой вопрос уже есть ответ.

Бесплатно и открыто

Лицензия MIT: можно использовать в коммерческих проектах, менять код и не платить роялти.

Работает везде

Любой современный браузер на компьютере, телефоне или в VR-шлеме. Пользователю ничего не нужно устанавливать.

Гибкость

Это библиотека, а не движок: она не навязывает структуру проекта. Её легко встроить в сайт на React, Vue или без фреймворка.

Есть куда расти

От готовых материалов до своих шейдеров, постобработки, WebXR и нового рендерера на WebGPU.

Стандартные форматы

Отлично поддерживает glTF — «JPEG для 3D». Модели из Blender, Maya или Cinema 4D загружаются за пару строк.

Богатая экосистема

React Three Fiber и drei для React, физика через Rapier или cannon-es, анимации через GSAP или Theatre.js.

Без зависимостей

Один пакет three. Подключается через npm или прямо с CDN, как на этой странице — без сборщика.

Чего Three.js не делает

Это не игровой движок. В нём нет визуального редактора сцен, физики, сетевого кода и системы сущностей — их добавляют сторонними библиотеками. API иногда меняется между версиями, поэтому при обновлении стоит читать заметки к релизу. За производительностью больших сцен тоже следите сами (советы — в разделе «Как начать»).

Где применяют

Для чего используют Three.js

Конфигураторы товаров

Покупатель крутит кроссовок, диван или автомобиль, меняет цвет и материал и сразу видит результат.

Визуализация данных

3D-графики, сети связей, глобусы с потоками данных. Например, интерактивный глобус на главной странице GitHub сделан на Three.js.

Промо-сайты и портфолио

Запоминающиеся лендинги с 3D-сценами, реагирующими на прокрутку и курсор. Частые гости в подборках вроде Awwwards.

Браузерные игры

От казуальных головоломок до 3D-шутеров. Вместе с физическим движком получается полноценная игра без установки.

Архитектура и недвижимость

Виртуальные туры по квартирам, планировки, визуализация зданий до начала стройки.

Наука и образование

Модели молекул, Солнечная система, анатомия, инженерные схемы, которые можно повернуть и рассмотреть.

VR и AR

Через WebXR те же сцены открываются в шлеме виртуальной реальности или поверх камеры телефона.

Карты и цифровые двойники

3D-рельеф, городские модели, мониторинг оборудования и производств в реальном времени.

Основы

Из чего состоит любая сцена

У любого приложения на Three.js одна и та же схема. Есть сцена с объектами и светом, есть камера, которая на неё смотрит, и есть рендерер, который много раз в секунду рисует то, что видит камера, в элемент <canvas> на странице.

Scene
Контейнер для всего, что нужно нарисовать. Объекты образуют дерево: если подвинуть родителя, вместе с ним сдвинутся и дети.
Camera
Чаще всего PerspectiveCamera — как человеческий глаз: дальние объекты меньше. Для чертежей и изометрии есть OrthographicCamera.
Geometry
Форма объекта — набор вершин и треугольников. Есть готовые: куб, сфера, тор, цилиндр, текст. Можно задать свою через BufferGeometry.
Material
Как выглядит поверхность: цвет, блеск, металличность, прозрачность, текстуры. MeshStandardMaterial — хороший выбор по умолчанию.
Mesh
Видимый объект: геометрия плюс материал. Его можно двигать (position), вращать (rotation) и масштабировать (scale).
Light
Без света большинство материалов чёрные. Обычно берут мягкий общий свет и один направленный, который даёт тени.
Renderer
Превращает сцену в картинку. Метод setAnimationLoop вызывает вашу функцию перед каждым кадром — там и происходит анимация.

Первая сцена

Вращающийся куб за 20 строк

Слева — весь код, справа — результат его работы. Именно этот код сейчас и выполняется.

import * as THREE from 'three';

const scene = new THREE.Scene();
const camera = new THREE.PerspectiveCamera(60, width / height, 0.1, 100);
camera.position.z = 3;

const renderer = new THREE.WebGLRenderer({ antialias: true });
renderer.setSize(width, height);
document.body.appendChild(renderer.domElement);

const cube = new THREE.Mesh(
  new THREE.BoxGeometry(1, 1, 1),
  new THREE.MeshStandardMaterial({ color: 0x2f6fd6 })
);
scene.add(cube);

const light = new THREE.DirectionalLight(0xffffff, 3);
light.position.set(2, 3, 4);
scene.add(light, new THREE.AmbientLight(0xffffff, 0.4));

renderer.setAnimationLoop((time) => {
  cube.rotation.x = time / 2000;
  cube.rotation.y = time / 1000;
  renderer.render(scene, camera);
});

Частицы

Сотни тысяч точек одним вызовом отрисовки: звёзды, снег, дым, искры, облака точек от 3D-сканеров.

Свои шейдеры

Когда готовых материалов мало, можно написать программу для видеокарты: волны, эффекты, процедурные текстуры.

Открыть пример →

GLTFLoader · AnimationMixer

Модели и анимация

Загрузка моделей из Blender и других редакторов вместе со скелетной анимацией и плавными переходами между движениями.

Открыть пример →

А ещё

  • Постобработка — свечение (bloom), глубина резкости, сглаживание, цветокоррекция через EffectComposer.
  • WebXR — режимы виртуальной и дополненной реальности встроены в рендерер (renderer.xr).
  • WebGPU — новый WebGPURenderer и язык шейдеров TSL; если WebGPU недоступен, он откатывается на WebGL 2.
  • Загрузчики — glTF, FBX, OBJ, STL, PLY, сжатие геометрии Draco, сжатые текстуры KTX2, HDR-окружения.
  • Управление камерой — OrbitControls, FlyControls, PointerLockControls для игр от первого лица.
  • Звук — пространственный звук, привязанный к объектам (PositionalAudio).
  • Текст и 2D — 3D-текст, спрайты, HTML-подписи поверх сцены (CSS2DRenderer).

Как начать

От нуля до своей сцены

  1. Подключите библиотеку

    Через npm, если у вас есть сборщик (например, Vite):

    npm create vite@latest my-3d-app -- --template vanilla
cd my-3d-app
npm install three

    Или без сборщика, через import map, как сделано на этой странице:

    <script type="importmap">
  { "imports": { "three": "https://cdn.jsdelivr.net/npm/three@0.170.0/build/three.module.js" } }
</script>

  2. Создайте сцену, камеру и рендерер

    Возьмите пример с кубом выше — это готовый каркас любого проекта.

  3. Добавьте управление и подстройку под экран

    import { OrbitControls } from 'three/addons/controls/OrbitControls.js';
const controls = new OrbitControls(camera, renderer.domElement);

window.addEventListener('resize', () => {
  camera.aspect = innerWidth / innerHeight;
  camera.updateProjectionMatrix();
  renderer.setSize(innerWidth, innerHeight);
});

  4. Загрузите настоящую модель

    Экспортируйте модель из Blender в формате .glb и загрузите её:

    import { GLTFLoader } from 'three/addons/loaders/GLTFLoader.js';
new GLTFLoader().load('model.glb', (gltf) => scene.add(gltf.scene));

  5. Опубликуйте

    Результат — обычный статический сайт. Его можно бесплатно разместить на GitHub Pages, Netlify или Vercel. Эта страница тоже лежит на GitHub Pages.

Советы по производительности

  • Ограничьте плотность пикселей: renderer.setPixelRatio(Math.min(devicePixelRatio, 2)).
  • Много одинаковых объектов рисуйте через InstancedMesh, а не тысячей отдельных мешей.
  • Сжимайте модели (Draco, Meshopt) и текстуры (KTX2), делайте стороны текстур степенями двойки (512, 1024, 2048).
  • Тени дороги: включайте их только у тех объектов и источников, где они заметны.
  • Освобождайте память видеокарты: у ненужных геометрий, материалов и текстур вызывайте .dispose().
  • Если сцена статична, рисуйте кадр только при изменениях, а не 60 раз в секунду.
